# 社員用マニュアル｜管理画面の運用手順

対象業務：
1. 楽曲売却申請の承認（と却下）
2. 承認済み売却申請が積みあがった場合の削除
3. パスワードが分からなくなったユーザーへのパスワード再設定メール再送

> このマニュアルは「管理画面の操作手順」です。各画面は管理者用のID/パスワード（Basic認証）でログインしてから操作してください。

---

## 0. 管理画面の入口

| 画面 | URL | 用途 |
|---|---|---|
| メイン管理画面 | `/admin` | 申請承認・**楽曲売却の承認/削除** |
| 財務管理 | `/admin/finance` | ユーザー一覧・**パスワード再設定メール再送** |

どちらもアクセス時にユーザー名・パスワードの入力（Basic認証）を求められます。社内で共有されている管理者アカウントを入力してください。

## 1. 楽曲売却申請の承認

ユーザーが楽曲の売却を申請すると、メイン管理画面に申請が表示され、社員が内容を確認して承認します。**承認するとそのユーザーにEPが付与されます。**

> **毎日1回確認：** 承認待ち（審査中）の申請を放置しないよう、**1日に1回はこのセクションを開いて新しい楽曲売却申請が届いていないか確認**してください。

### 手順

1. `/admin` を開く。
2. ページ内の **「🎵 楽曲売却申請管理」** セクションまでスクロールする。
3. 右上の **「更新」** ボタンを押すと、最新の申請一覧が読み込まれる。
4. 一覧で各申請の内容を確認する。
   - **ユーザー**：申請者のlogin_id
   - **楽曲タイトル** / **URL**（「リンク」をクリックすると別タブで開く）
   - **希望価格**：承認時に付与されるEP（例：`100 EP`）
   - **メモ**：申請者からの補足
   - **ステータス**：`審査中` / `承認済` / `却下済`
5. ステータスが **「審査中」** の行に、右端の操作欄へ **「承認」「却下」** ボタンが表示される。
6. 内容に問題がなければ **「承認」** を押す。
   - 画面上部に **「✅ 承認しました」** と表示されれば成功。
   - 申請者の **EP残高に希望価格分が加算** され、取引履歴（wallet_ledger）に記録される。
   - ユーザー側の画面には「売却申請が承認されました！」の通知が表示される。
7. 内容に不備がある場合は **「却下」** を押す。却下ではEPは付与されない。

### ⚠️ 注意点

- **承認・却下ボタンは確認ダイアログが出ず、押した瞬間に確定します。** 押す前に必ず申請内容（特にユーザーと希望価格）を確認してください。
- 承認は **二重付与されません。** すでに承認済みの申請をもう一度承認しようとしても、EPが重複して付与されることはありません。
- 承認後はステータスが **「承認済」** に変わり、承認/却下ボタンは消えます（代わりに削除ボタンが出ます。下記2参照）。

## 2. 承認済み売却申請が積みあがった場合の削除

承認した申請は一覧に **「承認済」** として残り続けます。件数が増えて見づらくなったときに、不要になった承認済みの行を一覧から削除して整理します。

### 手順

1. `/admin` の **「🎵 楽曲売却申請管理」** セクションを開く（必要なら「更新」を押す）。
2. ステータスが **「承認済」** の行には、右端に **「🗑 削除」** ボタンが表示される。
3. 不要な行の **「🗑 削除」** を押す。
4. 画面上部に **「🗑 削除しました」** と表示されれば成功。一覧から該当行が消える。

### ⚠️ 注意点（必ず読むこと）

- **削除できるのは「承認済」の行だけ**です。審査中・却下済の行には削除ボタンは出ません。
- **削除ボタンは確認ダイアログが出ず、押した瞬間に一覧から消えます。** 行を間違えないよう注意してください。
- 削除は **あくまで一覧（リスト）の掃除** です。**すでに付与したEPは戻りません（取り消されません）。** ユーザーが受け取ったEPはそのまま残ります。
- つまりこの削除は「処理が終わって不要になった承認済みレコードを片付ける」ためのものであり、承認の取り消しではありません。

## 3. パスワード再設定メールの再送（パスワードを忘れたユーザー対応）

ユーザーから「パスワードが分からなくなった／ログインできない」と連絡があった場合、財務管理のユーザー一覧から、本人の登録メールアドレス宛にパスワード再設定メールを再送します。

### 手順

1. `/admin/finance`（財務管理）を開く。
2. **「ユーザー一覧」** タブを開く。
3. 上部の検索ボックスに **login_id / メールアドレス / 名前** のいずれかを入力して対象ユーザーを絞り込む。
4. 一覧から対象ユーザーの行をクリックする。右側に詳細パネルが開く。
5. パネル内の **「アカウント操作」** にある **「登録メールアドレスにパスワード再設定メールを送る」** ボタンを押す。
6. 確認ダイアログ「`◯◯ 宛にパスワード再設定メールを送信します。よろしいですか？`」が出るので、宛先メールを確認して **OK** を押す。
7. **「✅ 送信しました（リセットリンクは72時間有効）」** と表示されれば成功。

### 送信後のユーザー側の流れ

- ユーザーの登録メールアドレスにパスワード再設定用のリンクが届く。
- リンクは **72時間（3日間）有効、1回限り** です。期限切れ・使用済みの場合は、再度この手順で送り直してください。
- ユーザーはそのリンクから新しいパスワードを設定します。
- **login_id（ログインID）は変わりません。** パスワードだけが再設定されます。

### ⚠️ うまくいかないとき（エラー表示と対処）

| 画面の表示 | 意味 | 対処 |
|---|---|---|
| ❌ 送信失敗: 該当ユーザーが見つかりません（メール表記揺れの可能性） | 入力した情報でユーザーを特定できなかった | メールアドレスのスペル・大文字小文字・余分なスペースを確認。login_idで検索し直す |
| ❌ 送信失敗: ステータスが approved ではないため送信できません | そのユーザーがまだ承認済み（approved）になっていない | 先に申請承認を完了させる。承認前ユーザーには送れません |
| ❌ 送信失敗: login_id またはメールアドレスが未設定です | 対象行に送信先情報がない | 該当ユーザーのデータを確認。判断に迷う場合は管理担当へ確認 |
| ❌ 通信エラー: … | 通信・サーバー側の一時的な不具合 | 少し待って「更新」後に再試行。続く場合は管理担当へ報告 |

> 補足：このボタンは **登録済みのメールアドレス宛にしか送れません。** ユーザーが「メールアドレス自体を変えたい」場合は、別途データ修正が必要になるため管理担当へエスカレーションしてください。

## 4. 換金申請の確認（Loofity・毎日チェック）

ユーザーからのEP換金申請は、Loofity管理シート（Googleスプレッドシート）に行として届きます。送金漏れ・対応遅れを防ぐため、**1日に最低1回はこのシートを開き、新しい換金申請が届いていないか確認してください。**

- シートを開く：[Loofity 換金申請シート](https://docs.google.com/spreadsheets/d/1saLEUcSmnUf-J6d-bT63UZeZoqolAmi6XpU7R704C_k/edit?gid=76671989#gid=76671989)
- 新規申請は行として追加されます。**created_at（申請日時）** や **status（処理状況）** を見て、まだ処理していない新着がないか確認してください。
- 処理方法や判断に迷う点があれば、自己判断せず管理担当へ確認してください。

> **お客様向け換金ガイド：** [EPをUSDTに換金する方法](https://www.loofity-game.com/ja/lifai/guide)（`https://www.loofity-game.com/ja/lifai/guide`）。ユーザーから「換金のやり方が分からない」と問い合わせがあったときは、このガイドのURLを案内してください。

### 各列（項目）の意味

| 列名 | 内容 |
|---|---|
| `request_id` | 換金申請ごとに発行される申請ID（例：LIFAI-R2I66Z）。問い合わせ対応時の照合キー |
| `plan` | 申請者のプラン（starter / infra など） |
| `ep_amount` | 換金を申請したEP数 |
| `ep_rate_jpy` | EPの単価（円）。例：0.5 = 1EP あたり0.5円 |
| `usdt_rate_jpy` | USDTの円レート。例：159.93 = 1USDT が159.93円 |
| `gross_usdt` | 手数料を引く前のUSDT換算額（＝ ep_amount × ep_rate_jpy ÷ usdt_rate_jpy） |
| `fee_usdt` | 差し引く手数料（USDT） |
| `net_usdt` | 手数料を引いたあと、実際にユーザーへ送金するUSDT額（gross_usdt − fee_usdt） |
| `source_wallet` | 送金元ウォレット（実際に出金する側。処理時に記入される） |
| `payout_network` | 送金ネットワーク（例：TRC20） |
| `payout_wallet` | ユーザーの受取ウォレットアドレス。ここ宛に送金する |
| `platform_wallet` | プラットフォーム側の管理用ウォレットID（例：LFW-…） |
| `status` | 処理状況（例：入金確認済み）。新着・未処理の判別に使う |
| `created_at` | 申請日時（UTC・協定世界時。日本時間は +9時間） |
| `申請者ユーザーID` | 申請したユーザーの内部ID（UUID） |
| `受領EP合計` | この申請で受領したEPの合計 |
| `不足EP` | EPが足りない場合の不足分（0なら充足） |
| `充当入金ID` | この換金に充当した入金（デポジット）のID |
| `送信元LIFAIOV_ID` | 処理した送信元（admin など） |
| `入金確認日時` | 入金が確認された日時 |
| `最終チェック日時` | 最後に状態確認・処理を行った日時 |

> 金額計算の関係：`gross_usdt = ep_amount × ep_rate_jpy ÷ usdt_rate_jpy`、`net_usdt = gross_usdt − fee_usdt`。実際にユーザーへ送るのは **net_usdt** です。

## 5. BP回復の確認・手動補充（随時チェック）

BPはプランごとの上限（`bp_cap`）に向けて**30日ごとに自動回復**します。ただし自動回復は**ユーザーがTOPページにログインしたときにだけ**実行されるため、しばらくログインしていない等の理由で、**31日以上経ってもBPが回復していないユーザーが出ることがあります。** その場合は利用者マスターシートを確認し、手動でBPを補充します。

> **随時チェック：** 「BPが回復しない」という問い合わせがあったときや、気づいたときに、下のマスターシートで対象ユーザーの状態を確認して補充してください。

- シートを開く：[利用者マスターシート](https://docs.google.com/spreadsheets/d/17rV59IjSXahNwmkBSE0OfjOmlk9_K1_SWxNJOXivBGw/edit?gid=442936583#gid=442936583)

### ① 未回復かどうかの確認手順

1. シートを開き、`Ctrl+F` で対象ユーザーを検索する（login_id / email / name）。
2. **bp_last_reset_at**（前回回復日）を見る。**空欄、または31日以上前**になっている。
3. それなのに **bp_balance**（現在BP）が **bp_cap（プラン上限）より少ないまま**なら、回復が走っていない＝補充対象。

### プラン別の bp_cap（上限）

| plan | bp_cap（上限） | 回復量の上限（cap×50%） |
|---|---|---|
| `500` | 1,000 | 500 |
| `2000` | 4,000 | 2,000 |
| `3000` | 8,000 | 4,000 |
| `5000` | 10,000 | 5,000 |

### ② 補充手順（シートを直接編集）

1. 回復量を計算する：`回復量 = min(bp_cap × 50%, bp_cap − 現在BP)`
   - ※ 現在BPがcap以上のときは回復0（補充不要）。capを超えて足さない。
2. 対象ユーザーの行の **bp_balance** を「現在値 ＋ 回復量」に書き換える。
3. 同じ行の **bp_last_reset_at** を**今日の日時**に更新する（これが次回30日カウントの起点になる）。

計算例（plan=5000 / bp_cap=10,000）：

| 現在BP | 回復量 | 補充後のbp_balance |
|---|---|---|
| 0 | 5,000 | 5,000 |
| 4,000 | 5,000 | 9,000 |
| 6,000 | 4,000 | 10,000（capちょうど） |
| 10,000以上 | 0（補充不要） | 変更なし |

> **直接編集の注意：**
> - このシートは**本番の利用者マスターデータ**です。**行・列を間違えて他の値を書き換えないよう**細心の注意を払ってください。
> - 編集するのは **bp_balance** と **bp_last_reset_at** の2つだけ。それ以外の列（pw_hash・残高以外の項目など）は触らない。
> - 判断に迷う場合（plan不明・cap以上なのに苦情がある等）は自己判断せず管理担当へ確認してください。

## よくある質問（FAQ）

**Q. 売却を間違えて承認してしまった。EPを取り消したい。**
A. 承認済みの「🗑 削除」では **EPは戻りません。** EPの取り消しは別途データ修正が必要です。管理担当へ連絡してください。

**Q. パスワード再設定メールが「届かない」と言われた。**
A. まず迷惑メールフォルダの確認を案内。そのうえで本マニュアル3の手順で再送（リンクは72時間で失効するため、古いメールではなく最新の再送リンクを使ってもらう）。

**Q. ボタンを押しても反応がない／エラーが出る。**
A. 画面右上などの「更新」を押して最新状態に読み直してから再試行。それでも解決しない場合は、表示されたエラー文をそのまま管理担当へ共有してください。
