# 動的ステーキングプール設計

**日付:** 2026-06-05  
**対象:** LIFAIOV / aisalon（両プロジェクト共通）  
**ステータス:** 承認済み

---

## 概要

BP・EPステーキングの利率を固定値からプールベースの動的レートに変更する。管理者が毎月プール量を設定し、ステーク開始時点の参加状況からレートを計算・確定する。参加者が増えるほど個人レートが下がる仕組みを「早期参加者ほど有利」として前向きに伝えるUXも合わせて実装する。

---

## 採用アプローチ

**シンプルプールモデル（Approach A）**

- 月次プールを管理者が手動設定（BP / EP 別々）
- レートはステーク開始時に確定し、満期まで保証
- 期間倍率で長期ロックを優遇
- 下限レートで最低保証を担保

---

## 利率計算ロジック

```
基本レート   = min(月次プール ÷ 現在の総アクティブステーク量, 100%)
期間レート   = 基本レート × 期間倍率
確定レート   = max(期間レート, 下限レート)
```

### 期間倍率

| ロック期間 | 倍率 |
|-----------|------|
| 30日 | 1.0× |
| 60日 | 2.5× |
| 90日 | 5.0× |

### 下限レート

| ロック期間 | 下限 |
|-----------|------|
| 30日 | 3% |
| 60日 | 7.5% |
| 90日 | 15% |

### 計算例

月次プール 10,000 BP、総ステーク量 100,000 BP の場合:

| 期間 | 基本率 | 倍率 | 確定レート |
|------|--------|------|-----------|
| 30日 | 10% | ×1.0 | 10% |
| 60日 | 10% | ×2.5 | 25% |
| 90日 | 10% | ×5.0 | 50% |

> 初期プールを調整すれば現行の固定レートと同値になるため、移行時のユーザー体験が断絶しない。

## データ構造

### 新設 GAS シート: `staking_pool`

| 列 | 型 | 内容 |
|---|---|---|
| `month` | string | `YYYY-MM` 形式 |
| `bp_pool` | number | 今月のBP報酬プール量 |
| `ep_pool` | number | 今月のEP報酬プール量 |
| `set_at` | datetime | 設定日時 |

### 既存シートの変更

- `staking` / `ep_staking` シートの `rate` 列に確定レートを書き込む（既存列、変更なし）
- 追加列不要

---

## GAS アクション

### `admin_set_staking_pool`
- 認証: adminKey 必須
- 引数: `{ month, bp_pool, ep_pool }`
- 処理: `staking_pool` シートに upsert（同月なら上書き）
- 戻り値: `{ ok, month, bp_pool, ep_pool }`

### `get_staking_pool_info`
- 認証: 通常キー
- 引数: なし
- 処理: 今月のプール設定 + `staking` / `ep_staking` シートから総ステーク量・参加人数を集計し、各期間の現在レートを計算して返す
- 戻り値:
```json
{
  "ok": true,
  "bp": {
    "pool": 10000,
    "total_staked": 45000,
    "participant_count": 23,
    "rates": { "30": 0.222, "60": 0.555, "90": 1.0 },
    "confirmed_rates": { "30": 0.222, "60": 0.555, "90": 0.50 }
  },
  "ep": { ... }
}
```
※ `confirmed_rates` は下限適用後の実際の確定レート

### `stake_bp` / `stake_ep` の変更点
- ステーク時に `get_staking_pool_info` 相当の計算を内部実施
- 計算した確定レートで利息・満期受取額を算出
- 既存の `rate` 列に書き込む（動作は変わらない）

## API

### `GET /api/staking?loginId=...&type=bp|ep`
- レスポンスに `pool_info` を追加
```json
{
  "ok": true,
  "stakes": [...],
  "bp_balance": 5000,
  "pool_info": {
    "pool": 10000,
    "total_staked": 45000,
    "participant_count": 23,
    "confirmed_rates": { "30": 0.10, "60": 0.25, "90": 0.50 },
    "gauge_pct": 45
  }
}
```
- `gauge_pct` = `total_staked / pool * 100`（ゲージ表示用）

## 管理画面

`admin/finance` の「月次集計」タブに **ステーキング設定セクション** を追加。

### 表示内容
- 今月のBPプール / EPプール 入力フォーム（保存ボタン付き）
- 現在の統計: 総ステーク量・参加人数・現在の各期間レート

## 考慮事項

- **EPステーキングは現在「準備中」のため**、EP側のプール計算は実装するがUIは引き続き無効化したままにする
- **月次プール未設定時のフォールバック**: プールが設定されていない月は前月の設定を引き継ぐ。それもなければ下限レートを適用
- **移行**: 既存ステーク（固定レートで記録済み）はそのまま維持。新規ステークからプール計算を適用
