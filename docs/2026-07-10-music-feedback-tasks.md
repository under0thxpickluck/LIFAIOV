## A-1. BPの毎月半分回復ができていない 【✅実装する】

### 現状と原因

実装自体は3層すべて存在する（GAS `monthly_bp_recover` = `gas/Code.gs:2925` / proxy `app/api/wallet/recover/route.ts` / 呼び出し `app/top/page.tsx:366`）。
原因の最有力は次の2つ（併発の可能性あり）：

1. **capマップに旧プラン値がない**：`gas/Code.gs:2973` の `BP_CAP_MAP_REC` は新値（34/57/114/567/1134）のみ。`plan` 列が旧値（30/50/100/500/1000）のユーザーは `unknown_plan` でサイレント失敗する。姉妹リポジトリ aisalon は旧値も含めて解決済み＋一括リカバリ関数 `bulkBpRecovery()` を保有。
2. **本番GASへのデプロイ未反映**：`gas/Code.gs` はリポジトリ上のコピーで、本番反映は手動デプロイが必要。

### 確定修正内容

**方式はTOP訪問時トリガーのまま維持（GAS定期トリガー化はしない）。**

1. **［調査］** 本番GASに `action:"monthly_bp_recover"` を直接POSTしてレスポンス確認。あわせて本番 `applies` シートの `plan` 列の実値一覧を確認する
2. **［GAS修正］** `gas/Code.gs:2973` `BP_CAP_MAP_REC` に旧値を追加：
   ```
   { "34":300, "57":600, "114":1200, "567":6000, "1134":12000,
     "30":300, "50":600, "100":1200, "500":6000, "1000":12000 }
   ```
   `get_balance` 側の `BP_CAP_MAP_BAL`（`gas/Code.gs:1956`）にも同じ旧値を追加する
3. **［GAS追加］** aisalon `gas/Code.gs:11765` の `bulkBpRecovery()` を移植し、デプロイ後にGASエディタから**1回手動実行**（全承認ユーザーへ即時回復＋`bp_last_reset_at` を当日に設定 → 以後30日サイクル）
4. **［デプロイ］** 本番GASへ再デプロイ
5. **［フロント確認］** `app/membership/page.tsx:16` の `PLAN_BP_CAP` は `"500":1000`（/5000プラン）が既に居るため**旧通常プラン "500"（cap 6000）とキー衝突する**。旧値ユーザーが実在した場合のみ、group判定を含む表示修正を行う（GAS側は `group` でマップが分かれているため衝突しない）

**やらないこと**：GAS時間主導トリガーでの全員自動回復（見送り）／回復方式そのものの変更

## B-1. 生成後の歌詞変更 【❌機能追加しない →「できない仕様」を明文化】

後から変更できない仕様とする。機能は追加せず、**ユーザーに伝わる説明文を追加する**。

### 確定修正内容（説明文の追加のみ）

1. `app/music2/page.tsx` … 結果画面の歌詞カード付近に注意書きを追加：
   > 「⚠️ 生成後の歌詞（歌唱内容）の変更はできません。歌詞を変えたい場合は新しく生成（BP消費）してください」
2. `app/music2/page.tsx` … チュートリアル `TUTORIAL_SLIDES` の完成スライド（4枚目）の本文にも同趣旨を一文追加

**やらないこと**：歌詞編集の永続化／履歴からの歌詞編集／「修正した歌詞で再生成」ボタン（すべて見送り）
